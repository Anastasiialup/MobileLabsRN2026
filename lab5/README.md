# 🎀 Лабораторна робота №5: Навігація в Expo Router

### Розробка каталогу товарів із захищеною навігацією та динамічними маршрутами

[cite_start]Цей проєкт є лабораторною роботою, присвяченою вивченню **file-based маршрутизації** у React Native за допомогою бібліотеки **Expo Router**[cite: 40, 42]. [cite_start]Додаток реалізує повноцінний цикл авторизації та перегляд каталогу товарів із детальною інформацією про кожен об'єкт[cite: 52].

-----

## Мета роботи

* [cite_start]**Ознайомлення з Expo Router**: Вивчення концепції файлової структури як маніфесту навігації[cite: 44, 45].
* [cite_start]**Layouts**: Використання архітектурного патерну макетів для збереження персистентності UI[cite: 46].
* [cite_start]**Захищені маршрути**: Реалізація механізму перенаправлення (Auth Guard) для неавторизованих користувачів[cite: 49, 51].
* [cite_start]**Динамічна навігація**: Створення сторінок з параметрами для відображення деталей товарів[cite: 76].

-----

## Функціональні вимоги

[cite_start]У додатку реалізовано наступні можливості[cite: 7, 8, 9]:
* [cite_start]**Авторизація**: Екрани входу та реєстрації з повною валідацією даних (Email через RegEx, перевірка довжини пароля)[cite: 61, 63].
* [cite_start]**Захищений каталог**: Доступ до списку товарів можливий лише після успішного входу[cite: 68, 69].
* [cite_start]**Каталог товарів**: Відображення списку об'єктів у `FlatList` із зображеннями, назвами та цінами[cite: 72, 73].
* [cite_start]**Деталі товару**: Динамічний перехід до повної інформації про товар за його унікальним `id`[cite: 77, 80].
* [cite_start]**Вихід із системи**: Можливість миттєвого завершення сесії через функцію `logout()` у глобальному контексті[cite: 74].
* [cite_start]**Обробка помилок**: Кастомний екран `+not-found` для неіснуючих посилань[cite: 83, 84].

## Технологічний стек

* **React Native & Expo SDK 55**: Основна платформа розробки.
* [cite_start]**Expo Router**: Бібліотека для навігації на основі файлової структури[cite: 44].
* [cite_start]**React Context API**: Глобальне керування станом авторизації (`AuthContext`)[cite: 56, 58].
* **Styled Components & StyleSheet**: Створення естетичного інтерфейсу в рожевих тонах 🎀.

## Структура проєкту

```text
├── app/                  # Папка маршрутів (Expo Router)
│   ├── (auth)/           # Публічна група (Вхід, Реєстрація)
│   │   ├── login.js
│   │   ├── register.js
│   │   └── _layout.js
│   ├── (app)/            # Захищена група (Каталог, Деталі)
│   │   ├── details/
│   │   │   └── [id].js   # Динамічний екран деталей
│   │   ├── index.js      # Головний екран каталогу
│   │   └── _layout.js    # Auth Guard (Redirect)
│   ├── _layout.js        # Кореневий макет (AuthProvider)
│   └── +not-found.js     # Обробка 404 помилок
├── context/
│   └── AuthContext.js    # Логіка авторизації
└── data/
    └── products.js       # Модель даних (масив товарів)
```

## Висновки (Відповіді на контрольні запитання)

1. [cite_start]**Перенаправлення**: Реалізується у файлі `_layout.js` захищеної групи через умовний рендеринг компонента `<Redirect />` залежно від стану `isAuthenticated`[cite: 50, 68].
2. **Link vs router.push()**: `<Link>` — це декларативний підхід, зручний для статичних посилань та доступності. [cite_start]`router.push()` — імперативний метод для виклику навігації всередині функцій (наприклад, після успішного запиту)[cite: 87, 88].
3. **Динамічні маршрути**: Створюються за допомогою назви файлу в квадратних дужках, наприклад `[id].js`. [cite_start]Параметри отримуються через хук `useLocalSearchParams()`[cite: 78, 89].
4. [cite_start]**React Context**: Це дозволяє уникнути "prop drilling" (передачі даних через багато рівнів) та забезпечує єдине джерело істини для статусу користувача в усьому додатку[cite: 90].
5. **Групи маршрутів**: Використовуються для логічного групування (наприклад, `(auth)` та `(app)`). [cite_start]Вони дозволяють створювати різні макети (`_layout`) для різних частин додатка, не змінюючи URL-адресу[cite: 48, 91].
```
